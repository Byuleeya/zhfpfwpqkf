# 코레일 공식 웹페이지 감시봇 v7 — 실제 달력 구조 적용

이 버전은 **실제 Railway 로그(v5: 날짜 선택 실패)**와 사용자가 공유한 코레일 검색 화면·열차 목록·**달력 팝업 HTML(calendar.txt)**을 대조해 수정했습니다. 날짜·시각 선택 코드는 달력 실제 마크업을 사용한 **로컬 Chromium UI 테스트**로 검증했습니다. **Railway의 실서버 전체 검색 흐름은 아직 성공 확인 전**입니다.

## 감시 조건

| 조건 | 값 |
|---|---|
| 출발일 | **2026-10-24(토) 00:00부터** |
| 출발역 | **나주** (v5의 목포에서 변경) |
| 기준 도착역 | **서울** |
| 함께 보기 | 인접역 포함, 서울·용산·수서 함께 보기 포함 |
| 대상 역 | **실제 나주 출발 → 서울·용산·수서 도착** KTX / KTX-산천 |
| 인원 | 성인 1명 |
| 검사 범위 | KTX 필터 적용 뒤 **더보기를 누르지 않은 첫 페이지(최대 10편)** |
| 알림 조건 | 일반실 또는 특실에 **정상 운임 표시** 혹은 **예약대기 신청 가능** 표시 |
| 제외 조건 | **456편 전부**, 입석+좌석, 입석, 자유석, 단순 매진 |
| 조회 | **20~30초 무작위 간격**으로 코레일 결과 페이지 새로고침 |
| 자동 종료 | **2026-10-25 00:00 KST** |

좌석을 자동 예약하거나 결제하지 않습니다. 보안·인증 절차를 우회하거나 IP를 변경해 접근 제한을 피하지 않습니다. 예약 가능 여부는 실제 코레일 화면에서 사용자가 다시 확인해야 합니다.

## v7 핵심 수정: 실제 코레일 달력

- 기존 v6는 `24` 숫자를 찾으려 했지만, 사이트의 달력은 **2026년 10월·11월·12월** 달력을 DOM에 동시에 만들어 둡니다. 따라서 뒤쪽 비활성 날짜와 혼동하거나 24일 링크 자체를 못 찾는 문제가 발생할 수 있습니다.
- 새 코드는 `.ReactModal__Content .type_date-pop_wrap` 안에서 **`p.date`가 `2026. 10.`인 달력만** 찾아, 그 달력의 `td:not(.disabled) a[aria-disabled="false"]` 안에 있는 `span.day`의 `24`를 선택합니다.
- 이어서 `.timeSelect .slideWrap`에서 **`00시`**를 선택합니다. 선택된 시간이 다른 경우에는 UI의 00시를 누릅니다. 화면에 00시가 표시되지 않고 슬라이더 이동도 불가능하면 임의 값을 만들지 않고 설정 실패로 남깁니다.
- 날짜·시각을 골라도 최초 폼이 바뀌지 않으므로, **`button.btn_bn-blue`의 `적용`을 누른 뒤** `#startDate` 값이 `2026-10-24... 00:00`인지 확인합니다.
- `2026-10-24`, `00:00`이 정확히 일치하지 않으면 **알림 판단을 하지 않고 설정 실패**로 남깁니다. 보호 장치를 우회하거나 프로그램 내부 React 상태를 직접 바꾸지 않습니다.
- 최초 10개 전체열차 목록에 무궁화호(1452)가 포함되더라도, **KTX 버튼을 선택한 후의 첫 최대 10편**만 평가합니다. 만약 KTX 필터가 선택되지 않으면 실패로 처리합니다.
- 456편과 입석+좌석, 자유석은 기존처럼 제외합니다. 도착역은 서울·용산·수서를 모두 포함하지만 **실제 출발역이 나주인 열차만** 검사합니다.

테스트: 사용자 제공 달력 HTML의 실제 10월·11월·12월을 갖춘 로컬 브라우저 재현 테스트를 포함하여 **29개 오프라인 테스트 통과**(제작 당시 기준). 웹사이트 JavaScript와 서버 요청은 Railway에서 별도 검증이 필요합니다.

## Docker / Railway 배포

v5는 Railway Build Logs에서 약 **973.5 MB Docker 이미지 Push에 31분 13초**가 걸렸습니다. Python 설치에 걸린 시간은 약 2초로, 문제는 빌드 코드가 아니라 이미지 전송 부분입니다.

v6부터 `mcr.microsoft.com/playwright/python:v1.55.0-noble` 대신 `python:3.12-slim-bookworm`에서 시작하여 아래처럼 **Chromium headless shell만 설치**합니다.

```dockerfile
RUN pip install --no-cache-dir -r requirements.txt \
    && python -m playwright install --with-deps --only-shell chromium
```

전체 브라우저 포함 이미지보다 작아질 것으로 기대하지만, **빌드 중 Chromium 다운로드·운영체제 패키지 설치 시간이 추가**됩니다. Railway의 실제 이미지 전송 속도/지연은 보장할 수 없으며, 새 경량 이미지의 실제 Railway 빌드 시간 및 성공 여부는 배포 로그에서 확인해야 합니다. 문제가 발생하면 Python/Chromium 패키지 설치 오류가 Build Logs에 표시됩니다.

1. ZIP을 압축해제하고 내부 파일 **전체**를 GitHub 기존 코레일 저장소 **최상위 폴더**에 덮어쓴 뒤 Commit.
2. Railway가 새 배포를 시작합니다. 기존 v5·v6와 v7을 동시에 실행하지 마세요.
3. `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`는 기존 Railway Variables를 그대로 재사용.
4. Deploy Logs에서 `v7-browser-naju-actual-calendar`가 표시되는지 확인.
5. `브라우저 최초 검색 검증 성공`과 `#1 검증성공`이 나오면 초기 검색과 첫 상태 검증에 성공한 것입니다.

## 검증과 오류 대응

```bash
python -m unittest discover -s tests -v
```

오프라인 테스트는 Playwright 모의 웹페이지뿐 아니라 사용자에게서 받은 실제 달력 HTML의 모달 조각도 사용합니다. 이를 토대로 10월 24일 선택, 00시, 적용, 뒤쪽의 비활성 11월·12월 24일 무시를 시험합니다. 실제 코레일 서버의 JavaScript 동작·네트워크와 동일하다고 보장할 수는 없습니다.

- 403/429, CAPTCHA, NetFunnel 대기 화면이 감지되면 인증/제한을 우회하지 않고 대기 또는 중단합니다.
- 달력·역 선택이나 검색 검증에 실패하면 예약 가능/매진으로 오인하지 않습니다.
- 첫 화면의 열차가 하나도 감지되지 않으면 정상 감시로 간주하지 않고 오류로 처리합니다.
- 동일한 상태로 열린 좌석이나 예약대기를 중복 발송하지 않도록 상태를 저장하지만, Railway 컨테이너 재시작 시 영구 디스크가 없으면 상태 파일이 사라질 수 있습니다.
- 첫 설정이 연속 3번 실패하면 Telegram 경고 후 중단합니다. 실패한 로그의 **후보=...** 및 **UI=...** 진단 부분을 보내주면 실제 달력 구조를 더 정확하게 수정할 수 있습니다.

**주의:** 웹사이트를 20~30초마다 새로고침해도 내부적으로 여러 네트워크 요청이 발생할 수 있습니다. 이는 코레일의 공식 자동화 API가 아니며 제한 기준을 알 수 없습니다. 대기·차단이 감지되면 요청을 무리하게 지속하지 않도록 설계했습니다.
